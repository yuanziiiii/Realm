# Relay Panel

轻量、个人自用的多服务器端口转发面板。通过一个控制台管理服务器、线路、转发规则、限速、流量统计和故障切换。

> 只做转发管理，不包含注册、套餐、支付、工单或多租户等商业功能。

[快速安装](#快速安装) · [使用方法](#使用方法) · [转发模式](#转发模式) · [日常维护](#日常维护) · [运维与排障](docs/operations.md)

## 工作方式

```text
服务器：安装 Agent，提供入口或出口能力
线路：组合入口、主出口、备用出口和两段转发引擎
规则：选择线路，只填写监听端口、落地地址和可选限速
```

支持两种线路：

```text
双端托管：客户端 → 入口 Agent → 内网/专线 → 出口 Agent → 落地
仅出口接管：客户端 → 已有入口转发 → 出口 Agent → 落地
```

## 核心能力

| 类别 | 能力 |
| --- | --- |
| 节点管理 | Agent 一键接入、自动识别公网/内网 IP 与网卡、在线状态和错误反馈 |
| 线路管理 | 双端托管、仅出口接管、一个主出口和多个备用出口 |
| 转发引擎 | 入口、出口可分别选择 nftables 或 Realm，支持混合使用 |
| NAT 出口 | 每个出口独立设置可用端口池，每条规则自动分配对应中继端口 |
| 故障切换 | 探测入口到出口的内网链路，自动切换出口 IP 和对应中继端口 |
| 业务健康 | 出口到落地的 ICMP 探测；TCP 规则额外检查真实业务端口 |
| 速率控制 | 每条规则独立设置上传、下载和 Burst，基于 nftables + tc |
| 流量统计 | 今日、本周、本月、本季度；全局与单规则折线图/柱形图 |
| 运维 | `zf` SSH 菜单、增量更新、密码重置、规则备份恢复和安全卸载 |
| 界面 | 深色、浅色和跟随系统；所有时间按北京时间显示 |

## 快速安装

### 1. 安装主控

准备一台 Debian 或 Ubuntu Linux 服务器，然后执行：

```bash
curl -fsSL https://raw.githubusercontent.com/yuanziiiii/Realm/main/scripts/install-control.sh | sudo bash
```

安装器会自动准备 Docker、启动服务并生成管理员密码。面板没有默认用户名，只需要使用安装完成时显示的密码登录。

默认端口是 `8080`。如需固定为 `18080`：

```bash
curl -fsSL https://raw.githubusercontent.com/yuanziiiii/Realm/main/scripts/install-control.sh \
  | sudo env RELAY_HTTP_PORT=18080 bash
```

默认安装目录为 `/opt/relay-panel`。已经安装后请使用在线更新，不要再次运行安装脚本。

### 2. 配置 HTTPS

推荐使用 1Panel、宝塔、Nginx 或 Caddy，把域名反向代理到：

```text
http://127.0.0.1:8080
```

如果安装时修改了端口，请换成实际端口。反向代理必须完整转发网页、`/healthz` 和 `/agent/v1/sync`。

- 使用 HTTPS 域名时，外部通常只需开放 `443/TCP`。
- 使用 `http://主控IP:端口` 直连时，需要在系统防火墙和云安全组放行该 TCP 端口。
- 不要通过公网明文 HTTP 传输 Agent Token。

### 3. 安装 Agent

在面板的“服务器”页面添加节点，选择入口、出口或两者兼用。面板会生成 Node ID、一次性 Token 和安装命令。

在目标服务器执行：

```bash
curl -fsSL https://raw.githubusercontent.com/yuanziiiii/Realm/main/scripts/install-agent-online.sh \
  | sudo bash -s -- \
      --controller https://你的面板域名 \
      --node-id 面板显示的NodeID
```

按提示粘贴 Agent Token。Token 不会写入 shell 历史，主控数据库也只保存摘要。

Agent 会主动连接主控，被控服务器不需要开放 Agent 管理端口。安装器支持 x86_64、ARM64，以及 Debian、Ubuntu、Alpine、RHEL 系发行版。

## 使用方法

### 第一步：确认服务器信息

Agent 首次上线会自动回填地址和网卡。请重点确认：

- 入口公网 IP 与公网网卡
- 入口前往出口的内网 IP 与内网网卡
- 出口接收入口流量的 IP 与网卡
- 出口访问落地使用的公网网卡

面板手工填写的值优先，不会被后续自动探测覆盖。地址或网卡修改后，相关规则会自动重新下发。

### 第二步：创建线路

在线路页面选择接管模式、入口、主出口、备用出口、端口池和转发引擎。这些关系只配置一次，以后可以被多条规则复用。

### 第三步：创建转发规则

选择线路后填写：

```text
协议：TCP / UDP / TCP+UDP
入口监听端口：客户端连接的端口
落地 IP 与端口：最终业务服务器
上传/下载限速：可选，0 表示不限速
```

保存后，主控会自动为各节点生成配置并下发。修改规则不需要登录入口或出口服务器。

## 转发模式

### 双端托管

入口和出口都安装 Agent，适合入口与出口之间有内网、CNIX、专线或其他可达地址的场景。

```text
客户端 → 入口公网 IP:入口端口
       → 出口内网 IP:自动分配的中继端口
       → 落地 IP:落地端口
```

线路中可以分别选择：

- 入口引擎：处理“入口公网端口 → 出口内网 IP:中继端口”
- 出口引擎：处理“出口中继端口 → 落地 IP:端口”
- 主出口与备用出口：按优先级自动切换
- 每个出口的 NAT 端口池：例如 `1301-1349,25000`

#### 多出口与 NAT 端口

不同出口可以使用完全不同的服务商端口：

| 出口 | 内网 IP | 可用端口池 | 本规则分配端口 |
| --- | --- | --- | --- |
| 主出口 A | `10.0.0.2` | `1301-1349` | `1301` |
| 备用出口 B | `10.0.0.3` | `2301-2349` | `2301` |

落地地址可以保持相同。主出口故障时，入口目标会自动从 `10.0.0.2:1301` 切换到 `10.0.0.3:2301`；恢复稳定后自动回切。

当前是主备切换，不是多出口负载均衡。出口段会提前下发到所有主备出口，因此切换时只需要更新入口目标。

### 仅出口接管

第一跳已经自行配置时，只需在出口安装 Agent：

```text
客户端 → 已有入口转发
       → 出口接入 IP:入口规则指定的端口
       → 落地 IP:落地端口
```

此模式只配置出口引擎。规则监听端口必须与已有入口规则的目标端口一致；如果出口是 NAT 机器，还必须位于服务商分配的端口池内。

## 引擎选择

| 引擎 | 特点 | 建议用途 |
| --- | --- | --- |
| nftables | 内核转发，吞吐高、资源占用低 | 大多数入口和高流量出口 |
| Realm | 用户态进程，配置灵活、排障直观 | 需要 Realm 特性的出口或特殊协议场景 |

入口和出口互不绑定，例如可以使用 `入口 nftables → 出口 Realm`。只使用 nftables 时，安装 Agent 可添加 `--skip-realm`。

nftables 当前以 IPv4 转发为主，落地地址需填写 IPv4；Realm 可使用域名或 IPv6。

## 健康检查与自动切换

- 入口 Agent 探测每个出口的内网 IP，显示延迟和丢包。
- 连续 3 次失败后切换到健康备用出口。
- 主出口连续 3 次恢复后按优先级回切。
- 从未成功回应 ICMP 的地址不会仅因 ICMP 失败触发误切换，仍会参考 Agent 在线状态。
- 出口 Agent 探测落地 IP；TCP 和 TCP+UDP 规则还会完成一次 TCP 握手后立即断开，不发送业务数据。

UDP-only 业务仍应通过实际客户端测试，TCP+UDP 的端口健康结果只代表 TCP 部分。

## 限速与流量统计

上传指客户端到落地，下载指落地返回客户端。双端托管在入口计量，仅出口接管在出口接入侧计量，每条链路只统计一次。

面板提供：

- 今日、本周、本月、本季度总量
- 单条规则独立统计
- 上传、下载实时速率
- 折线图和柱形图切换
- 北京时间自然周期

实时速率只在流量页面或规则详情打开时每 10 秒刷新。SQLite 保留最近 7 天分钟明细，并长期保存每日汇总，个人规模通常只占用数 MB 到几十 MB。

## 日常维护

主控和 Agent 安装完成后，SSH 中统一使用：

```bash
zf
```

菜单会自动识别机器角色，可完成更新、重启、日志、健康检查、密码重置和安全卸载。也可以直接更新主控：

```bash
curl -fsSL https://github.com/yuanziiiii/Realm/releases/latest/download/update.sh | sudo bash
```

更新 Agent：

```bash
curl -fsSL https://github.com/yuanziiiii/Realm/releases/latest/download/update-agent.sh | sudo bash
```

更新器只在发现新版本时载入预构建镜像，并保留数据库、密码、端口、Node ID、Token 和现有规则；失败会自动回滚。

规则备份与恢复位于“系统设置 → 转发配置备份”。导出文件包含线路、引擎、端口池、规则目标和限速，不包含密码、Token、流量及探测历史。

更多命令、故障排查、数据备份和安全说明见 [运维与排障](docs/operations.md)，版本更新机制见 [UPDATE.md](UPDATE.md)。

## 运行要求

- 主控：推荐 Debian 12 或 Ubuntu 22.04/24.04，个人使用 1 核 1 GB、10 GB 磁盘即可。
- Agent：Linux x86_64/ARM64，需要 `CAP_NET_ADMIN`；资源占用主要取决于连接数和规则数量。
- 低内存主控首次安装会自动准备 Swap；在线更新不会在服务器重新编译。

## 项目范围

当前版本面向个人部署和小规模节点，暂不包含 IPv6 nftables NAT、WebSSH、通知告警、商业计费和多租户系统。
